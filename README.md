# Jeremy Guill Portfolio CMS

## What this is

A CMS-backed portfolio site and single-owner admin for Jeremy Guill. The public site is server-rendered; the owner manages content through the admin or the `flask content` CLI.

Features:

- Homepage, work index and long-form case studies with an at-a-glance panel, table of contents and pager
- Experience page, blog with RSS feed, and a contact form with a success state
- Light and dark themes, responsive accessible navigation, and a print stylesheet
- Complete SEO metadata: Open Graph/Twitter cards, JSON-LD, sitemap, `security.txt`
- Passkey-protected admin, strict CSP, and optional cookie-less Umami analytics
- Content-hashed static URLs with long-lived cache headers and self-hosted fonts

## Architecture

A Flask application (`src/portfolio`) backed by PostgreSQL 17 through SQLAlchemy and Alembic migrations. A separate worker process handles background jobs (email and similar). Everything runs under Docker Compose (`web`, `worker`, `db`, and the optional `analytics` service); the `web` container serves the app on port 7777 and sits behind an existing host-level nginx/openresty reverse proxy that terminates HTTPS. There is no JavaScript build step: CSS and the small amount of JS are plain static files.

## Local Setup

1. Install Python 3.14, `uv`, and Docker.
2. Install dependencies with `uv sync --locked`.
3. Run tests with `uv run pytest -v`.
4. Start the local stack with `docker compose up --build -d`.

Open `http://127.0.0.1:7777/` locally.

## Useful Commands

- `uv run flask --app portfolio db upgrade`
- `uv run flask --app portfolio content seed-initial`
- `uv run ruff check .`
- `uv run mypy src`
- `uv run pip-audit`
- `docker compose config`
- `docker compose logs -f web worker`

## Asset Pipeline

Brand assets (favicon, social card, WebP backgrounds, portrait variants) are generated by `scripts/make_brand_assets.py`:

```bash
uv run python scripts/make_brand_assets.py
```

There is no npm or JS build; static files under `src/portfolio/static` are served as-is with content-hashed URLs.

## Content Workflow

- Seed the initial content: `uv run flask --app portfolio content seed-initial`
- Set social links and availability: `uv run flask --app portfolio content set-profile --linkedin https://www.linkedin.com/in/NAME --github https://github.com/NAME --availability "Open to full-time roles."`
- Apply owner-reviewed Markdown copy: `uv run flask --app portfolio content apply-copy --dry-run`, then without `--dry-run`.

In production, prefix these with `docker compose exec web`.
